# Chog Cult implementation plan

Design: `docs/superpowers/specs/2026-10-19-chog-cult-design.md`. Everything lives in an independent
`cult/` package with its own `package.json`, lockfile and tests. Never edit `city/`, the root Solidity
code, the root lockfile or `.env`.

Each task ends with its tests passing. Fixture mode must keep working without RPC, a wallet, model
keys or a running City.

## Task 1: Package and pure rules engine (done 2026-10-19)

- Scaffold `cult/` with TypeScript (strict), Node 24, Vitest.
- `src/shared/identity.ts`: `AgentIdentity`, `AgentKey`/`makeAgentKey`, `ControlObservation` and
  `ChainReader`, copied exactly from the City design.
- `src/rules.ts`: versioned constants (cycle and phase lengths for production and demo, cooldown,
  influence weights, presence cap) and the decree catalog with trait affinities.
- `src/engine/agentVote.ts`: deterministic persona vote from traits.
- `src/engine/resolveCycle.ts`: eligibility, epoch fencing, overrides, influence, ties, control,
  decree choice and reputation.
- Tests: every rule in the design's section 3, including ties, zero-vote factions, flash-joins,
  cooldowns, a transfer mid-vote, the presence cap, and identical output for identical input.

## Task 2: Fixture world (done 2026-10-19)

- Fixture Chogs with traits and owners, a fixture `ChainReader` with scripted transfers, and a fake
  City feed of `visit`/`greet` events.
- A CLI that runs N demo cycles in memory and prints each outcome, so the engine is visible before any
  server exists.

## Task 3: Persistence and scheduler (done 2026-10-19)

- PostgreSQL migrations for the tables in design section 5.
- A scheduler that advances phases under the `cult_runtime` lock and commits each transition and
  cycle result atomically, with input and result hashes. Duplicate or retried resolves return the
  stored result.
- Agent votes are cast at Vote open. Presence is ingested from the City feed, deduplicated by City
  revision.
- Tests against a real Postgres: restart mid-cycle, duplicate resolve, downtime catch-up limit.

## Task 4: Public API and live feed (done 2026-10-19)

- `GET /api/cult/snapshot`, `/api/cult/places`, `/api/cult/factions`, `/api/cult/agents/:agentKey`.
- SSE with durable replay by revision, mirroring City. Event types as built: `phase_changed`,
  `debate`, `votes_cast`, `override`, `member_changed`, `control_changed`, `city_gap`,
  `city_late`, `schedule_gap`, `place_control_changed`, `cycle_resolved`, plus `reset` for a
  cursor outside the 10,000-revision replay window.

## Task 5: Holder actions and auth (done 2026-10-19)

- SIWE login, matching City's rules.
- `PUT /api/cult/members/:agentKey` and `PUT /api/cult/votes/:cycle/:agentKey/:place`. Each checks
  fresh control, ownership epoch, idempotency key, cooldown and phase, and returns
  `SWITCH_COOLDOWN`, `NOT_ELIGIBLE`, `VOTING_CLOSED`, `NOT_CONTROLLER` or `OWNERSHIP_UNAVAILABLE`
  as appropriate.
- Transfer handling: reset to Unaligned and `abstain`, void the current vote and overrides, keep
  history.

## Task 6: `/cult` interface (done 2026-10-19)

- The three places with ruler and decree, Crown and Chaos panels, a live phase countdown, a debate
  feed labelled `Scripted`, and a vote tally.
- An owner panel: faction, stance and per-place override, with cooldown and closing-time messages.
- Accessible list alternative, mobile tabs, reduced motion, matching City's conventions.

## Task 7: City integration and demo (done 2026-10-19)

- Live City reader against City's public API, with graceful degradation and gap labelling when City
  is down.
- A two-viewer demo script covering the design's section 7 acceptance list, plus a short runbook.
- Hand the teammate the `place_control_changed` contract so City can render banners.

## Later (not in v1)

Holder-founded cults, a Soul `DebateProvider`, alliances, and decrees with gameplay effects (these
need a joint economy design with City).
